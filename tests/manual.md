# Manual checklist (phase 1)

Things that pytest and the Node tests cannot check: the real server, real phones, two people at once, screen readers. Go through it once on the deployed copy (after following `README.md` on a clean server) and again after bigger changes. Tick a box only after you have seen it.

Devices to use: an iPhone with Safari, an Android phone with Chrome, a desktop browser, and a second phone for everything marked "two devices". Test with the final URL (and the WhatsApp in-app browser where noted).

Items that are only a question for the organizer are at the end, in "Decisions to confirm".

## 1. Deploy, server and files

- [ ] **Clean server:** following only `README.md` (install Docker, clone, supply the three secrets as environment variables, create `data/` with the right owner, `docker compose up -d --build`, add Caddy), the container becomes „healthy“ and the page opens. Note anything in the README that was wrong or missing.
- [ ] **Pred cestou switch (T-069):** with no `INFO_ENABLED` line in `/etc/cabin/secrets.env`, the board is hidden and `docker compose logs cabin | grep "Pred cestou"` says the section is off; after adding `INFO_ENABLED=true` and `docker compose --env-file /etc/cabin/secrets.env up -d`, the board shows and the log line says on.
- [ ] **Version after deploy:** after `docker compose up -d --build` on the server, `curl -s http://127.0.0.1:8010/api/health` returns `{"ok":true,"version":"<the version in pyproject.toml>"}` (not `unknown`), and the image builds with `pyproject.toml` present (T-035; Docker build not run by the tester).
- [ ] **HTTPS works:** `https://<host>/` opens with a valid certificate, `http://` redirects to it, and the page works on a phone over mobile data.
- [ ] **Final URL and sub-path:** under the real URL (and, if used, a sub-path such as `/cabin/`) the page loads and the `api/...` calls work (relative paths).
- [ ] **Non-root, read-only container:** `docker compose exec cabin id` shows a non-root user. The app can write `data/` (the first start created `data/cabin-data.yaml` with the right owner), and it cannot write elsewhere (`docker compose exec cabin touch /app/x` fails). `ss -ltn` on the host shows port 8010 only on `127.0.0.1`, never on `0.0.0.0`.
- [ ] **Restarts on failure and after reboot:** `docker kill <container>` brings it back within a few seconds, and after a reboot of the server the app is up again without a manual step (`restart: unless-stopped`). `docker compose top` shows one uvicorn process with `--workers 1`.
- [ ] **Restart keeps the data:** assign a few places, `docker compose restart` (and once `docker compose down` followed by `docker compose up -d`), reload the page: everything is still there, and the version in `data/cabin-data.yaml` did not go back.
- [ ] **Secrets as environment variables:** `GROUP_CODE`, `ADMIN_CODE` and `SECRET_KEY` (at least 32 characters) reach the container only through the environment (`docker compose exec cabin printenv GROUP_CODE`). With one of them missing, `docker compose up` refuses with a „set …“ message. With a too short `SECRET_KEY` the container exits and the English reason is in `docker compose logs`. The code values never show up in the logs. There is no `.env` on the server (not in the project directory and not in the image: `docker compose exec cabin ls -a /app`).
- [ ] **Corrupt data file:** stop the container, break `data/cabin-data.yaml` (a bad indent, then an unknown slot ID), start it. The app does not start, and `docker compose logs` shows an English message that names the file and the line or entry. After fixing the file (and `docker compose start`) it runs again.
- [ ] **Timezone data:** `docker compose exec cabin python -c "import zoneinfo; print(zoneinfo.ZoneInfo('Europe/Bratislava'))"` works, and the times in `audit.yaml` and in the page make sense.
- [ ] **Guest info in the container (T-057):** `config/info.yaml` reaches the container (`docker compose exec cabin cat /app/config/info.yaml` shows the file) and the page's „Pred cestou“ texts come from it. Change one line (e.g. `bring`), `docker compose restart`, reload: the new text shows and `/api/state` carries it as `info`. A broken file (e.g. an unknown icon) makes the container exit with the message naming the path and the value.
- [ ] **Audit and backup are created:** after a real write behind Caddy, `data/audit.yaml` grew by one YAML document with the right `source` (`map` or `form`) and an anonymous `client_id`, and `data/backups/` holds a new copy. After many writes (check after the first real evening of use) `data/backups/` never holds more than 5000 files (`backups_keep`).
- [ ] **Backup restore drill:** copy `data/` away (README, "Back up"), make a change on the page, then follow README "Restore from `data/backups/`" (`docker compose stop`, copy a backup over `cabin-data.yaml`, `chown`, `docker compose start`): the page shows the restored state.
- [ ] **Hand fix:** README "Fix the data by hand" works as written (stop, edit, start, and a mistake is reported at start).
- [ ] **Changed layout:** after editing `config/cabin.yaml` and `docker compose restart` (no rebuild), an open tab and a reloaded tab show the new layout (the `ETag` changes, no stale 304).
- [ ] **Not reachable from outside:** `https://<host>/data/cabin-data.yaml`, `/data/audit.yaml`, `/config/app.yaml`, `/.env`, `/files/mapa-nahlad.html`, `/docs` and `/openapi.json` all return 404, also through the Caddy config and not only straight to the container.

## 2. Group code, cookie and limits

- [ ] **Group code works:** opened from the WhatsApp link for the first time, the code screen appears. A wrong code shows a Slovak message, the correct code opens „Kto si?“.
- [ ] **Renamed cookies and keys (T-027):** on a phone that used the trial page before the rename, the code screen appears again after the update, and „Kto si?“ asks for the party again (the cookies and `localStorage` keys from before the rename are dropped on purpose). The places on the map are still there. Check it once on iPhone Safari and once on Android Chrome.
- [ ] **Cookie is kept:** behind Caddy over HTTPS the cookie is stored (`Secure`, `HttpOnly`, `SameSite=Lax`) and the page works after closing and reopening the tab. Check iPhone Safari, Android Chrome and the WhatsApp in-app browser (it may not keep cookies, note what happens).
- [ ] **Remembered choices:** after choosing a party, close the page and open it from the link again: the party is remembered.
- [ ] **Wrong-code limit is per real client IP:** 11 wrong codes from one phone give the „príliš veľa pokusov“ message. A second phone on other mobile data can still join with the correct code. This proves `X-Forwarded-For` is trusted only from Caddy.
- [ ] **Shared Wi-Fi:** several friends on the same Wi-Fi join within one minute with the correct code, and nobody gets the limit message (only wrong codes count).
- [ ] **Changing a code:** after changing `GROUP_CODE` where you keep it and running `docker compose up -d` (a plain `restart` does not pick up new values), an already joined phone gets the code screen again. After changing only `ADMIN_CODE`, the group access stays.
- [ ] **Write limit:** 30 quick taps from one phone within a minute (for example clearing and assigning repeatedly): the 31st shows the Slovak „príliš veľa zmien“ style message, and the phone recovers after about a minute.
- [ ] **Logs:** `docker compose logs` shows the app lines (`join as ...`, `wrong code attempt from <ip>`) once each (not doubled), with the real client IP behind the proxy (not the Docker gateway address).

## 3. Two devices

- [ ] **Same free slot at once:** two phones tap „Zapísať nás sem“ on the same free bed within the same second. Exactly one gets it. The other sees the „Toto miesto má … už …“ message naming the winner, its pending figure disappears and its map is correct again. Nothing ends up half written.
- [ ] **Overlapping places at once:** two parties take overlapping places at the same moment (for example both want the same double bed on one night). Exactly one booking wins whole, the other is rejected whole, and no party holds only half of its request.
- [ ] **A change shows up live:** after phone A changes the data, phone B shows it within about 1 s without a reload. If the stream is blocked (for example a proxy that buffers), the page falls back to polling every 30 s and „aktualizované pred … s“ counts up and resets after each poll. Returning to the tab from another app refreshes at once.
- [ ] **Live stream (T-052):** with the page open on two phones, phone A's change appears on phone B within about a second (the event stream, not the 30 s poll). Lock the phone or switch apps for a minute on one device: after returning, it shows the current state at once (lock and unlock phone B while phone A changes things: B reconnects and shows the changes made meanwhile). Behind Caddy, the stream is not buffered (see the production proxy check below).
- [ ] **Stream on a phone (T-053):** with the page open on phone A, lock the screen or switch app for a minute: on phone B the party drops off the online row at once (the stream of a hidden tab is closed). Back on A the map is current without a reload and no extra state request is needed. Airplane mode on A for 50 s: the line „aktualizované pred …“ appears; back online it returns to the online row.
- [ ] **Restart with open streams (T-052):** with two phones connected, restart the trial server (or run `docker compose restart` on the real deploy): the restart finishes within about 5 s (not hung), and the pages reconnect by themselves after the server is up and show the current state, without a reload.
- [ ] **Online chip is live (T-050/T-053):** open the page on phone B while phone A shows the map: the chip of B appears on A within about 1 s, and disappears within about 1 s of closing B's tab.
- [ ] **Production proxy check (T-054):** `curl -N -H 'Cookie: <group cookie>' https://<host>/api/events` shows `event: state` at once (not after a delay) and then `event: ping` every 20 s. Without the cookie it answers 401.
- [ ] **Shortened stay on two phones:** phone A confirms the freed places, phone B shows them free within about a second.
- [ ] **Pending state:** „ukladám“ (semi-transparent figures) is visible for a moment on a slow connection (throttle to 3G), and the map returns to the server state after a rejection.

- [ ] **Move mode on a phone:** after the sheet closes the bar appears above the scene and the scene may jump down a little. The next tap still lands on the intended bed, and „Zrušiť“ and „Táto noc / Všetky noci“ are easy to hit.
- [ ] **Stay shortening:** shortening a party's stay in the form on a phone: the page names the slots that will be freed first, and after saving they are free on the map of the other phone.
- [ ] **Missing places:** the red „V sobotu ti chýba 1 miesto“ style sign shows when a party needs more places than it holds, and goes away when it has enough.
- [ ] **Day-only party, bed panel (T-037):** create one in the party form with „Prídem len na návštevu“ and one day (T-038), pick it in „Kto si?“ and tap a bed on the map: the panel says „Prídeš len cez deň, posteľ nepotrebuješ.“, both assign buttons are disabled, and „Upraviť príchod a odchod“ is still there. The night signposts show „nie si tu“ and no figure walks to a bed. Check on iPhone Safari and Android Chrome.
- [ ] **Walk to the bed (T-017):** with a party of 2 adults and 1 kid and no beds on the night, tap a single bed and „Zapísať nás sem“: one figure walks from the meadow to the bed slowly and smoothly in about 3 s (slower at the start and the end, no jerks, no flicker), passes over the beds and under the signs, and stays fully opaque all the way even though the server has long confirmed. - [ ] **Walk and night switch (T-017):** tap a bed and switch the night on a signpost during the walk: no figure is left walking or hanging on either night, and the booking shows on the right night. „Zapísať „Meno“ na celý pobyt“ walks on all booked nights, „Len na …“ only on the selected night, the other nights change at once.
