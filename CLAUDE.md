## Python tooling: uv only

Python 3.12 and all dependencies are managed with **uv**. Do not use pip, `requirements.txt` or hand-made venvs.

- Pin the Python version with `uv python pin 3.12` (writes `.python-version`).
- Add runtime deps with `uv add <pkg>` and dev deps (pytest, httpx) with `uv add --dev <pkg>`. They are declared in `pyproject.toml` and locked in `uv.lock`, which stays in the repo.
- Install with `uv sync` and run everything through `uv run`, e.g. `uv run pytest`, `uv run pytest tests/test_validate.py::test_name`, `uv run uvicorn app.main:app --host 127.0.0.1 --port 8010`.
- The Node tests of the page logic need no uv: `node --test tests/js/`.

## Development workflow (agents and task board)

Work is organized as a kanban board in `tasks/` (`todo`, `in-progress`, `review`, `testing`, `done`). A task's folder is its status, and the format is in `tasks/README.md`. Six project subagents in `.claude/agents/` own the stages:

| Agent | Model | Role |
| --- | --- | --- |
| `product-owner` | opus | Sets priorities and scope on the board, follows the organizer's requests, moves phase 2 items; does not code |
| `analyst` | opus | Reads `proposal.md`, writes ordered tasks into `tasks/todo/` |
| `ux-designer` | opus | UX and game design: fills `## Design` of tasks marked `UX: yes`, makes prototypes in `design/`, proposes fixes when something looks wrong or empty; does not code |
| `developer` | sonnet | Takes one task at a time (fixes first): `todo → in-progress → review` |
| `reviewer` | opus | Two review rounds: `review → in-progress` (changes) or `→ testing` (approved) |
| `tester` | haiku | Verifies acceptance criteria: `testing → done` or back to `in-progress` |

Subagents cannot launch each other, so the **main session is the orchestrator**. Loop: run `analyst` once, then repeat until `todo`, `in-progress`, `review` and `testing` are empty:

1. Anything in `testing/` → `tester`.
2. Anything in `review/` → `reviewer`.
3. Anything in `in-progress/` → `developer` (fix it).
4. Otherwise a ready task in `todo/` → `developer`. If it is marked `UX: yes` and its `## Design` is still empty, run `ux-designer` on it first.

Run `ux-designer` also, before any coding, when the organizer says something looks wrong, empty or dull, or asks for a new screen, panel, animation or game element (organizer's decision of 26. 10. 2026). Pass it the complaint and the screenshot path, show the organizer its recommendation in short, and then implement it (as a task or a small direct fix). Small pure-bug fixes with no visible design choice skip it.

Run one task per developer call. To keep the main session's context small, pass subagents only the task id (they read the task file themselves), do not paste their reports back into later prompts, and run `/compact` between tasks. Avoid needless send-backs: each `in-progress ↔ review` cycle costs the developer and the reviewer (opus) a full read again. Tasks whose dependencies are all in `done/` may run in parallel only if they touch different files. When a task fails review round 2, report it to the user instead of looping. Phase 2 tasks stay blocked until the organizer confirms. When all work is done, list the open decisions from `proposal.md` with the defaults used.

**Git:** only the orchestrator commits and pushes. Commit once per task when it reaches `done/`, staging only that task's files plus its task file, with the message `T-00x: <title>`. Agents never commit, but the reviewer and tester may use `git status` and `git diff` to see what changed since the last commit. When two tasks run in parallel, the diff contains both, so look at the files in the task's scope. After each task commit, the orchestrator pushes `main` to `origin` (organizer's decision of 23. 10. 2026); agents never push, and nothing is force-pushed. Never commit `.env` or `data/`.

**Trial server (restart after every task):** the organizer tries each change on a phone through Tailscale (`tailscale serve --https=8443` → `127.0.0.1:8010`, tailnet only). ## What this is

A small web app for assigning sleeping places at a cabin (chata) for the event 29. 10. (Thursday) – 1. 11. 2026 (Sunday) (three nights, ~8–10 parties, 13–18 people, 20 slots of which 2 are "tight"). Friends tap a pixel-art top-down map to pick who sleeps where each night. There are no accounts. Access is a shared group code, plus an admin code for the organizer. The people use it from a WhatsApp link on mobile.

## Hard constraints from the brief

- **Languages:** all UI text is **Slovak**, informal (tykanie), with typographic quotes „ “. This covers scene text, panels, user-facing messages, and room and bed names in `config/cabin.yaml`. Code, identifiers, comments, logs, startup/config errors, tests and README are **English**.
- **The server sends no Slovak text.** Errors carry a stable `code`, an English developer `message` and optional `params`. The page maps `code` (+ `params`) to Slovak messages in one lookup table in `static/js/logic-errors.js`, with a generic Slovak fallback for unknown codes.
- **Mobile first** (~380 px wide), then desktop.
- **Frontend has no build step and no framework**: plain HTML and CSS in `static/index.html` and the JS split into plain scripts in `static/js/` (`logic-*.js` pure logic, `app-*.js` DOM and requests), served by FastAPI (organizer's decision of 24. 10. 2026). No ES modules and no bundler: the scripts share one global scope and load in the order of the `<script>` tags in `index.html`, logic first, `app-start.js` last. **Every script URL ends in `?v=__ASSET_VERSION__`**, which `GET /` replaces with a hash of the release version, `index.html` and `static/js/*.js` (`PageRenderer` in `app/main.py`), so browsers never run stale code and every release shows the „Nová verzia“ sign. When adding a script, list it in `index.html` with that query, and keep new logic in `logic-*.js` so Node can test it. **One exception to both rules:** the map's 3D world is drawn with the vendored Three.js r158 (`static/vendor/three.min.js`, plain-script build, licence in `three.LICENSE`). It is the only script outside `static/js/`, it is a library and not a build step, and it is pinned by its own version, `?v=r158`, instead of `__ASSET_VERSION__` (change the number when the file changes).
- Pixel art is custom, in an old top-down RPG style. Use **no characters, art or names from Pokémon or other games**.
- Backend is **FastAPI + Pydantic v2 + PyYAML + uvicorn, Python 3.12**. **No database and no external services**, except the optional Claude API in phase 2 and Twilio Verify for the phone login (organizer's decision of 25. 10. 2026; `app/sms.py`, called over `httpx`, swappable fake client in tests, `SMS_FAKE=1` logs the code on the trial server).
- Phase 1 is no-AI and has no admin tools. Phase 2 (admin tools: signup lock, export, delete party, key icon and panel, task T-009; and free-text signup via Claude API) is optional and **not to be built until the organizer confirms** after trying phase 1.
- Section "Otvorené rozhodnutia" in `proposal.md` lists open decisions. Do not decide them yourself. Use the stated defaults and list them for the organizer at the end of the work.

## Planned architecture

Single uvicorn process with **one worker**, bound to `127.0.0.1` (default port 8010) behind a Caddy/nginx HTTPS proxy. Single-process is a correctness requirement. The `asyncio.Lock`, rate limits and phase-2 conversations all live in process memory.

- `app/main.py`: routes, cookies, serving `static/`.
- `app/store.py`: YAML read and atomic write, the lock, `version`, backups, audit.
- `app/models.py`: Pydantic models (`Party`, `Slot`, `State`, action requests).
- `app/validate.py`: **pure functions** that check writes (free slot, presence, move, stay shortening). They are the only place rules live. The server always re-checks, and the page may pre-check only for speed.
- `app/ratelimit.py`: in-memory limits (30 writes/min per client, 10 code attempts/min per IP).
- `app/events.py`: the in-memory hub of the live event streams (`GET /api/events`, SSE): coalescing per connection, caps (4 per client, 200 total), pings, presence by open stream. Another reason the app must stay one process.
- `app/seen.py`: last seen per party (`data/seen.yaml`) and the online list.
- `app/sms.py`: Twilio Verify client for the phone login (proposal section „Prihlásenie telefónom“). A party with a `phone` is protected: only a device whose signed `party_auth` cookie lists it (or the admin) may write to it (`login_required`). The phone is never sent in `/api/state`, SSE, audit or logs; state carries only `phone_hint` (last 3 digits).
- `app/llm.py`: phase 2 only. Forced tool `propose_signup` (schema generated from Pydantic), with a swappable client for tests.
- `config/cabin.yaml`: event, nights, and the full layout (rooms, beds, slots, SVG coordinates for viewBox 380×496, plus the `houses` list that groups rooms under roofs). Written by the organizer and sent to the page inside `/api/state`, so the map and the validation share one source. The layout is a guess from a preview, so keep it data-driven and never hardcode geometry in code. Bed `kind` (`bed2`, `bunk`, `mats`, `sofa`, `sofa1`, `stove`, `bed1`, `cot`) determines figure placement.
- `config/app.yaml`: limits, model name, `backups_keep`.
- `config/info.yaml`: the „Pred cestou“ content (water, packing list, sleeping, menu, program), written by the organizer, sent in `/api/state` as `info`; missing file = feature off. Per-party progress is `briefing` in `cabin-data.yaml` (`POST /api/briefing`). `design/info/index.html` is the approved prototype (reference only, never served).
- `data/` (git-ignored, created on first start): `cabin-data.yaml`, `seen.yaml` (last seen per party), `audit.yaml` (one YAML document per write, separated by `---`), `backups/`. `data/` must never be served statically.
- `Dockerfile`, `compose.yaml`: the deploy (organizer decision of 22. 10. 2026: Docker instead of systemd). Inside the container uvicorn listens on `0.0.0.0:8010`; compose publishes it only on host `127.0.0.1:8010`, passes the secrets as environment variables (no `.env`), mounts `./data` read-write and `./config` read-only. `deploy/Caddyfile` is the proxy example. `tests/manual.md` is the manual checklist.

### Data model essentials

- A night is identified by its start date (`2026-10-29` = Thu→Fri; nights are 2026-10-29, 2026-10-30, 2026-10-31). `sleeping` is `night → slot → party_id`, so double-booking is impossible by structure, and a free slot is simply absent.
- Party `id` is `p-` plus 6 random chars. The name is case-insensitively unique and can be renamed without touching `sleeping`. The server assigns the color from the 12-color palette listed in the proposal's "Vzhľad" section unless the request carries its own `color` (T-031, organizer's decision of 24. 10. 2026: chosen on create, overridable on edit; free hex colors allowed, but the server rejects ones too light or too dark with `invalid` and a reason in `params`).
- Needed slots per night = `adults + kids − kids_in_parents_bed`. A party is present on night *n* if `arrive ≤ n < leave`.
- Dates and times in YAML must be **quoted strings** so PyYAML does not parse them into `date` objects.

### Write path and file safety

Every write action runs under the one lock: load current state → validate via `validate.py` → write → bump `version` → append audit → return `{ok, state}`. Writes are atomic: temp file in the same directory, `fsync`, `os.replace`. A timestamped backup goes to `data/backups/` before each write (keep the last `backups_keep`, 5000 in `config/app.yaml`). Use `yaml.safe_load` and `safe_dump(allow_unicode=True, sort_keys=False)` only. At startup, validate the data file with the Pydantic models and against `cabin.yaml` (unknown slot, party or night; duplicate slot IDs). On error, refuse to start with a precise message. A missing or empty file is created.

### API conventions

Success is `200 {"ok": true, "state": {...}}`. Errors are `{"ok": false, "error": {"code", "message"}, "state": {...}}` with an English developer `message` and optional `params` (e.g. `night`, `party_name`); the page never shows `message` and builds the Slovak text from `code`. Codes: `bad_code` 401, `forbidden` 403, `signup_closed` 403, `login_required` 403, `phone_mismatch` 403, `bad_sms_code` 401, `sms_unavailable` 503, `slot_taken` 409, `not_present` 409, `duplicate_name` 409, `unknown_slot` 404, `unknown_party` 404, `invalid` 422, `rate_limited` 429. Everything except `/`, static files, `/api/health` and `/api/join` needs the signed group cookie (itsdangerous with `SECRET_KEY`; HttpOnly, Secure, SameSite=Lax; group 30 days, admin 12 h). Admin endpoints need the admin cookie. Codes are compared with `secrets.compare_digest`. The page sends an `X-Client-Id` header (random ID in `localStorage`) for audit and limits. `GET /api/state` supports `ETag` by `version` plus the presence data (304). The page sends the party chosen in „Si: …“ as `X-Party-Id`; the server records its last seen time in `data/seen.yaml` (`app/seen.py`, throttled, no `version` bump, backup or audit) and returns `state.presence`. Online = an open event stream, or a plain request within 75 s for a polling page. `GET /api/events?party=…&client=…` (SSE; `EventSource` cannot send headers) sends `event: state` at once and after every committed write (hooked into the store commit), `event: presence` when the online set changes, and `event: ping` every 20 s. uvicorn must run with `timeout_graceful_shutdown=3` (`--timeout-graceful-shutdown 3`), otherwise open streams hang a restart. When signup is locked, writes return `signup_closed` unless the admin cookie is present. The full endpoint table is in `proposal.md`.

### Frontend behaviour worth knowing

- **The whole app is one page, and that page is the pixel map.** Event title and dates, the three night signposts with occupancy, the party table and the locked-signup sign are drawn inside the SVG scene (positions in `config/cabin.yaml` under `map.scene`, content from `/api/state`). The „?“ icon in the scene opens „Návod“ (the four steps) as a centred window. The party table has two parts, „Noc“ (a row per party, a column per night) and „Cez deň“ (day-only visits, with the „spolu na jedlo“ row). „Si: …“ with the age of the data and the status sign of my party (missing, fewer, extra, ok) are a fixed bottom HUD in HTML outside the SVG, so they stay put while the map is panned or zoomed; the scene is fitted above it. Once per page load, after the splash is gone, the map starts 2× zoomed on the top of the scene and eases out to the fitted view over 2.8 s (`introStartView`/`introViewAt`, `app-zoom.js`) to show that the map can be moved; a touch, wheel or key on the map, a resize or the move mode stops it where it is, an opened panel does not (a new visitor sees it zoom out behind the semi-transparent backdrop of the automatic „Kto si?“), and with `prefers-reduced-motion` it does not run (organizer's decision of 24. 10. 2026). There is no separate header, list view or overview page. Party form, „Kto si?“, the WhatsApp summary text and the admin controls open as panels over the map. A visually hidden text summary serves screen readers.
- The map is SVG with `shape-rendering="geometricPrecision"` (antialiased, smooth edges; the 3D layer uses `antialias` and a pixel ratio of `min(devicePixelRatio, 1.5)`, `ISO_PIXEL_RATIO_MAX`, lowered from 2 for phone render cost, organizer's decision of 27. 10. 2026). The scene uses fixed colors and is not inverted in dark mode. Panels follow the light/dark colors in the proposal's "Vzhľad" section.
- Isometric 3D map (T-130 to T-134): the pixel map is a 3D world seen from the south-east and above (`static/js/app-iso.js`, Three.js, orthographic camera with a slight perspective), with the svg on top of it. The projection is pure and shared in `logic-iso.js` (`isoPoint`, `isoScene`): the flat plan in `config/cabin.yaml` stays the single source, the svg draws beds' tap areas, boards and icons at projected points, and `isoSync()` points the camera at the svg's viewBox after every pan or zoom, so both layers line up. The board block (title, slider, signposts, party table, icon grid) stands upright above the world. Without WebGL the svg draws a flat ground fallback (`drawBase`) and the app still works. The static mesh is built lean (T-142): `IsoBoxes` keeps boxes until `flush()` and drops faces another box covers, crowns merge equal outside faces, and the pine tops are coloured faces, not slabs. Quality adapts by itself (`isoQualityStep` in `logic-iso.js`, `isoQualityFrame` in `app-iso.js`): frame intervals over 40 ms for 2 s while animating step down pixel ratio 1.5 -> 1.25 -> 1, then soft -> hard shadows; it tries a step up after 20 s of animating at a level if at least 90 % of those frames were within budget (a few slow frames do not matter), a step down within 20 s of a climb counts as a failed climb and doubles the next wait (up to 8x), and a climb that holds resets the wait to 20 s; the fps meter shows `q0`..`q3`. Test hook: `isoQualityExtraMs` adds to every measured interval. People (T-138): the figures are 3D too (sit and lie dolls from boxes, my party's blinking yellow frame, meadow waiters, walkers), built in `app-iso-people.js` with the pure part (colours, poses, steps) in `logic-iso-people.js`; the svg sprites stay only as the no-WebGL fallback and after a lost WebGL context. Dolls pop in, shake out, fade at 06:00, hop and lift on the same 30 fps update (smooth, lengths from elapsed ms; none of it with `prefers-reduced-motion`). Light and life: the time slider lights the world through `isoLight(lightAt(h))` (sun to dusk orange to moon blue, room and window glow, campfire), and chimney smoke, campfire flames, falling leaves and fireflies move on one shared 30 fps update (`ISO_TICK_MS` 33 ms; campfire flicker and ring blink keep their old 125 ms on/off rhythm) driven by `requestAnimationFrame` alone (no timers); with `prefers-reduced-motion` nothing animates and each change renders once, and while the tab is hidden nothing is drawn. Four view angles (T-143): the camera azimuth is 45 (default, from the south-east), 135, 225 or 315 (`ISO_ANGLES`, `isoScene(layout, {azimuth})`, `app.viewAngle`, stored as `cabin-view-angle`; +90 turns the map clockwise on screen). The projection, back-to-front order, hit regions and figures all come from the one projection; the angle-dependent parts follow `isoBackSides(azimuth)`: which outline walls and corner posts stand tall (the two sides facing away from the camera), chimney side, room plate wall, bunk rail, tap-area bounds, and the sun and the roof colours (`isoSunAzimuth`, `isoSunSlope`: the light turns with the view so the shadows look the same from every side). `setViewAngle(angle)` in `app-turn.js` (the test hook; T-144 adds buttons and the swing) stores it and rebuilds the world and the svg (the angle is part of the layout key); a map at rest lands on the new rest view, a zoomed one keeps the plan point under the screen centre and the zoom relative to the rest (`isoTurnView`, `isoUnpoint`); open houses stay open. Roofs and walls (T-137): at the rest view every house is closed (tall walls all round, gable roof in its `houses[].roof` colours from the pure `isoRoofs` in `logic-iso-roof.js`, chimney through the roof, ridge sign „voľné: N“ or „plno“ for the chosen night; room labels, bed tags, figures and bed tap areas are hidden, the bed buttons stay for keyboard and screen readers). A tap on a closed house opens it and eases the view to it (it never assigns); zooming to 1.6× the rest zoom opens all houses, back to 1.15× or „Celá mapa“ closes all; move mode, Tab focus on a bed and a pending write open the house concerned. Opening is a smooth 750 ms animation on the same 30 fps update (roof lifts and is gone, front walls sink), instant with `prefers-reduced-motion`. Meshes and steps are in `app-iso-roof.js`, state, zoom rule, taps and signs in `app-houses.js`.
- Day and night (`static/js/logic-daynight.js` pure, `app-daynight.js` slider and time-lapse, organizer's decision of 26. 10. 2026): a time slider is drawn in the scene between the title board and the signposts (`map.scene.time`; its hour scale follows the signposts, hidden in move mode). Nights change at 06:00 (the last night is clamped), and at each 06:00 the figures swap with a fade. Only a tap on a night signpost, the „Ťukni sem“ sign in the HUD or the rail runs the time-lapse (dusk, night, dawn); dragging the knob sets the time directly. Page load opens at noon of the chosen night; „Kto si?“ and live updates switch the night at once, and `prefers-reduced-motion` skips animations. There is no clock board. The world itself is lit in 3D (`isoLight`, see above); only a weak tint over the boards stays in the svg, so signposts and the party table stay readable.
- Live updates over SSE (`static/js/app-live.js`, pure parts in `logic-live.js`, organizer's decision of 25. 10. 2026): the page loads `/api/state` once, then keeps an `EventSource` open while the tab is visible (closed at once when hidden or on `pagehide`, since iOS freezes hidden pages; the server keeps the party online for `STREAM_GRACE` = 10 s after its last stream closed, reopened on return or reconnect, reopened when silent for 45 s). States apply only if their `version` is not older than the shown one. If the stream cannot deliver for 60 s, the page falls back to polling `/api/state` every 30 s (10 s timeout) and retries the stream every 3 min. Under „Si: …“ the HUD shows the online parties as shirt-letter chips, or „aktualizované pred …“ only when there is a problem. Updates are optimistic ("ukladám", semi-transparent) and roll back to server state with the server's reason on rejection.
- FPS meter (developer aid, organizer's request of 27. 10. 2026): off for everyone by default; `?fps=1` in the page address turns it on for that device (remembered in `localStorage` as `cabin.fps`), `?fps=0` turns it off. It shows 3D renders per second, the average and worst CPU time of a render over 2 s the GPU frame time (`EXT_disjoint_timer_query_webgl2`, else „gpu ?“), draw calls and triangles of the last frame, and the pixel ratio (`fpsSetting`, `fpsStats`, `fpsText` in `logic-iso.js`, `app-fps.js`). The 3D layer renders only on change, so 0 fps at rest is correct.
- All human-provided text goes in via `textContent`, **never `innerHTML`**.
- Beds are focusable `role="button"` elements with screen-reader labels. Respect `prefers-reduced-motion`. Touch targets are at least 44 px.
- Page logic (presence, needed slots, warnings, WhatsApp "Prehľad na poslanie" text, figure positions) is in **separate pure functions** so it can be tested in Node without a browser.
- If the app might run under a sub-path, use relative API paths.
